# 주간 보고서 (2026-05-12 → 2026-05-26)

GroundedDNA 프로젝트의 2주차 진행 보고서. 지난 보고서(5/12) 이후 발생한 주요 변경 사항을
정리한다. 모든 결과는 frozen SigLIP2-base backbone, 36-bit DNA hash (6 codebooks × 3 codons × 2 bases),
batch size 64, 60 epoch, AdamW 옵티마이저(`proj_lr=1e-3`)의 공통 세팅에서 측정되었다.

- **Flickr25k setting1**: 5K train / 2K query / 23K database
- **MSCOCO setting1**: 10K train / 5K query / 107K database / 80 class

---

## 1. 핵심 요약 (TL;DR)

| 지표 | 5/12 시점 | 5/26 시점 | Δ |
|---|---|---|---|
| Flickr25k 비지도 SOTA (mAP) | v6 baseline ~0.66 (CIBHash 0.6543 위) | **v81a 0.6879** | **+0.034** |
| Flickr25k P@1 | n/a (CIBHash 0.835) | **v81a 0.7900** | — |
| Flickr25k unique code 비율 | v34 0.381 (text-off) | v81a 0.346 (text-on) | — |
| MSCOCO 비지도 SOTA (mAP) | 미측정 (CIBHash 0.5051 단독 우위) | **mscoco_v81a 0.4891** | gap −0.049 → **−0.016** |
| MSCOCO P@1 | n/a | mscoco_v81a 0.6352 | — |

지난 2주 동안 **Flickr25k와 MSCOCO 양쪽에서 비지도 SOTA를 모두 갱신**했으며, MSCOCO에서는
강력한 외부 baseline (CIBHash 0.5051)과의 mAP gap이 0.049 → 0.016 으로 절반 이상 좁혀졌다.
두 데이터셋에서 **동일한 routing policy(v81a 계열)** 가 SOTA를 달성한다는 점이 가장 큰 구조적
교훈이다.

## 2. 비지도 SOTA 갱신 흐름

지난 2주의 핵심 결과는 다음 세 단계의 누적 개선으로 요약된다.

```
v29 (5/15)  → v57 (5/20)  → v62b (5/21)  → v81a (5/26)        : Flickr25k
                              ↓
                         mscoco_v69a (5/23) → v78a (5/25) → mscoco_v81a (5/26) : MSCOCO
```

### 2-1. v29 — paired-aug NtXent (5/15, 토대 마련)
모든 후속 실험의 학습 신호가 된 **CIBHash 스타일 paired-augmentation NtXent**를 DNA code 위에서
처음 적용. v27b의 batch-top-k cosine pseudo-positive 대비 mAP 0.5639 → **0.6627** (+0.099).
이 시점에서 처음으로 CIBHash baseline(0.6543)을 mAP 기준으로 추월했다.

### 2-2. v34 (5/18) — text-off SOTA mAP 0.6696
v30a (MLP hidden=768 adapter) + Sinkhorn router의 **top-k=2 hard mask** 조합. 텍스트 입력 없이
순수 augmentation-NtXent만으로 mAP 0.6696 / unique 0.381 / dead 0.000 달성. 이후 시기 동안
모든 "text-off" 비교의 기준점이 되었다.

### 2-3. v49 → v57 (5/20) — 텍스트 경로 복원과 Wasserstein 정렬
- V4 caption cache (Qwen-VL 기반 6-슬롯 prompt) + dynamic-τ NtXent + routing top-p 0.7
  + Sinkhorn ε anneal (1.0 → 0.1) + visual-text Wasserstein loss 라인업.
- **v49** (`lambda_wasserstein=0.02`): peak mAP **0.6705** — 텍스트 경로가 복원된 이후 첫 SOTA.
- **v57** (`lambda_wasserstein=0.02 → 0.05`): 단일 λ 변경으로 peak **0.6742** / final 0.6676.
  이 단일 변경이 v46→v57 family에서 가장 효과적인 단일 노브 변경이었다.

### 2-4. v62b (5/21) — Residual-Conditioned Codon Head (mAP 0.6778)
- 단일 변경: codon head에 **post-VQ residual `(z − q)`을 γ 가중치로 부가 입력으로 공급**.
  `CodonHead(quantized_token, γ · residual)` 형태로 `Linear(2D→D)` 후 기존 3-codon FC 통과.
- γ 스윕: γ=0.1 → 0.6734 / **γ=0.3 → 0.6778 ★** / γ=0.5 → 0.6646. γ=0.3이 sweet spot.
- 핵심 기여: codebook lookup·routing은 그대로 두고 **codon decoding 단계에서만** 잔차를 주입했기
  때문에 compositional 구조 (codebook utilisation entropy 0.90 유지, dead 0.003)는 보존되면서
  같은 codeword를 공유하는 이미지들 사이의 변별력을 회복.
- 5/21~5/25 동안 Flickr25k SOTA로 자리잡았다.

### 2-5. mscoco_v69a → v78a (5/23 → 5/25) — MSCOCO에 맞는 구조 발견
- **mscoco_v69a** (5/23): codon head를 position-specific (`Linear(256,4)` 3개)로 변경. 단일
  변경으로 MSCOCO mAP **0.4563 → 0.4795 (+0.023)**, P@1 +0.022. *Flickr25k 에서는 같은 변경이
  −0.008 손해* — dataset-paradigm-specific인 흥미로운 비대칭.
- **v78a** (5/25): K=128 → K_max=192 **adaptive codeword split** (warm-start + 10/20/30 epoch에서
  split-score 기반 codeword 2-means 분할). 분할의 69%가 C_0 (global codebook)에 흡수되어
  K_0=128 → 153으로 성장, mAP **0.4856** 달성. MSCOCO drop ablation에서 C_0 drop ΔmAP = −0.019
  로 dominant 채널임을 confirm한 이론적 예측과 정확히 일치.
- Flickr25k에서는 같은 알고리즘이 mAP 0.6660 (−0.012)로 regression. C_0가 Flickr25k에서는
  bottleneck이 아니기 때문 (drop ΔmAP = −0.004). **알고리즘은 동일, split target만 데이터셋별로
  다름.**

### 2-6. v81a / mscoco_v81a (5/26) — 현재 SOTA: Confidence-Adaptive Top-p Routing
양 데이터셋의 현재 SOTA. 핵심 아이디어는 patch별 **Sinkhorn routing 확률의 row-normalised
신뢰도**에 따라 top-p sparsity를 동적으로 조절하는 것.

**구현 핵심**:
- Sinkhorn routing 결과 `P_prob: [B, N, M]`을 row-normalisation 한 뒤 각 patch의 max probability
  `c = max(P_norm)`를 신뢰도로 사용.
- `tau(c) = tau_min + (tau_max − tau_min) · clamp(c, 0, 1)` — confident patch일수록 sparse하게,
  ambiguous patch는 dense하게 routing.
- masked transport mass는 원래 Sinkhorn row mass로 다시 renormalise하여 OT marginal은 유지.
- 인터벌 스윕 결과 **`(tau_min, tau_max) = (0.5, 0.9)`** 가 두 데이터셋에서 모두 최적.

**Flickr25k v81a (v62b 위에 적용)**:

| 지표 | v62b (이전 SOTA) | **v81a** | Δ |
|---|---:|---:|---:|
| mAP | 0.6778 | **0.6879** | **+0.0101** |
| P@1 | 0.7625 | **0.7900** | **+0.0275** |
| P@10 | 0.7587 | **0.7890** | +0.0303 |
| P@100 | 0.7573 | **0.7810** | +0.0237 |
| P@1000 | 0.7445 | **0.7607** | +0.0162 |
| Unique code | 0.0745 | **0.3462** | +0.272 (4.6×) |
| Val effective-k (ep59) | — | 3.319 | — |

소프트 sparsity 커리큘럼 (val effective-k 4.79 → 3.32) 덕분에 **모든 retrieval depth(P@1~P@1000)와
unique-code 비율을 동시에 개선**한 첫 routing variant. 이전 시도(v80 hard threshold gate)는
gate가 끝까지 활성화되지 않아 effectively always-top-2 routing이 되어버려 mAP 0.6467로 regression.
**핵심 차이는 row-normalised 신뢰도** 사용 (raw Sinkhorn mass는 너무 작아서 threshold가 활성화되지
않음).

**MSCOCO mscoco_v81a (mscoco_v69a 위에 적용)**:

| 지표 | mscoco_v69a | v78a (이전 final SOTA) | **mscoco_v81a** | Δ vs v78a |
|---|---:|---:|---:|---:|
| mAP | 0.4795 | 0.4856 | **0.4891** | **+0.0035** |
| P@1 | 0.5830 | 0.6058 | **0.6352** | **+0.0294** |
| P@10 | 0.5685 | 0.5720 | **0.6200** | +0.0480 |
| Unique code | 0.0162 | 0.0165 | **0.0613** | +0.045 (3.7×) |

같은 routing policy가 **MSCOCO에서도 SOTA를 갱신**. 단, peak mid-eval은 v78a ep9 (0.4984)이
mscoco_v81a ep9 (0.4955)보다 높음 — final-checkpoint SOTA이지만 best-peak는 아님. 향후 best-epoch
checkpointing 또는 sparsification schedule cap이 필요.

**구조적 정당성**: v81a는 단순히 mAP가 가장 높을 뿐 아니라 **compositional code의 구조적 주장
(codebook redundancy 감소 + 모든 codebook 활성 + graded contribution)도 정량적으로 만족**시킨다.
세부 NMI / drop ablation / per-codebook B1 분석은 §4 참조.

## 3. 의미 있는 실패 사례 (교훈)

### 3-1. v80 — 신뢰도 게이트 비활성화 (5/26)
v80a/b/c에서 confidence threshold 0.55 / 0.60 / 0.65로 ambiguity-aware top-k routing 적용.
**세 threshold 모두 수치적으로 동일한 결과** (mAP 0.6467, effective-k 1.984, top-1 fraction 0.0):
Sinkhorn row-mass가 너무 작아 raw probability가 0.55를 넘는 patch가 없었다. 이 실패가
v81a의 row-normalisation 도입 동기. **교훈**: routing scale의 절대값을 가정한 threshold 설계는
실패하기 쉽다; 정규화된 분포 위에서 정의해야 한다.

### 3-2. v73 — 글로벌 NtXent와 position-specific decoding의 충돌 (5/23)
mscoco_v69a 위에 18-codon 전체에 대한 글로벌 NtXent (λ=0.05) 추가 → **P@1 −0.20, mAP −0.047의
catastrophic collapse**. v69a의 이득이 *position-specific decoding* (각 codon position이 다른 4-class
projection 학습) 에서 온다는 사실 확인. 글로벌 supervision은 모든 18 position을 공통 subspace로
끌어당기므로 specialization과 명시적으로 충돌. **글로벌 supervision과 position-specific decoding은
상호 배제 design axis**라는 결론.

### 3-3. v74 — loss_anchor가 EMA 모드에서 dead-weight (5/23)
`--lambda_anchor 0` 실험이 v62b와 **bit-exact 동일한 결과** 산출. 분석 결과 EMA codebook 모드에서는
`local_codebook_mean_anchors`가 모두 detached buffer로부터 유도되어 gradient가 흐르지 않음.
즉 모든 기존 SOTA 결과 (v34, v49, v57, v62b 등)는 `lambda_anchor=0.05` 항이 사실상 무효였던 상태로
얻어졌다. **이전 결과는 그대로 유효**하지만 페이퍼 narrative와 loss 표에서 항목을 정정해야 함.

### 3-4. v77 — From-scratch 큰 K의 한계 (5/25)
MSCOCO에서 K=192 / K=256으로 from-scratch 학습 → 둘 다 K=128 (v69a) 대비 −0.03 ~ −0.04 mAP regression.
원인: 10K train sample / 192~256 codeword ≈ 50 sample/codeword 의 noisy EMA update. **adaptive K
(v78a)** 가 다음 단계로 자연스럽게 도출된 동기. *"capacity sweet spot은 train size에 매여 있고
무작정 K를 키워서는 안 된다"* 는 결론.

### 3-5. v83 — Entropy-only adaptive top-p의 dense-routing 문제 (5/26)
v81a의 heuristic-looking `(tau_min, tau_max)` 신뢰도 공식을 routing entropy 기반 신호로 대체 시도.
결과: routing이 거의 모든 patch에서 dense하게 유지 (effective-k 4.96 → 4.65), 의미 있는 specialization
생성 실패. mAP 0.6615 (v81a 대비 −0.026). **교훈**: confidence와 entropy는 routing의 다른 측면을
포착하며 entropy 단독은 너무 균일한 분포에서 신호가 약해진다.

### 3-6. v78c/d 및 cosine VQ 호환성 (5/25~5/26)
Cosine-distance VQ codebook lookup은 K=64 + from-scratch + adaptive K 결합에서 mAP −0.051 의 가장
큰 v78 regression 발생 (v78d). 그러나 K=32 from-scratch 또는 L2-trained warm-start에서는 정상
동작. **Cosine VQ는 (1) 적은 K로 angular separation 확보, 또는 (2) L2 사전학습된 codebook 위에서만
사용 가능하다**는 페이퍼-수준 limitation finding.

## 4. Compositional 분석 (5/26) — Paper-worthy 구조적 증거

### 4-1. 핵심 발견 — 세 패러다임의 비교

페이퍼의 "compositional code" 주장은 단순 unique-code 비율이 아니라 **(i) codebook 간 redundancy
감소**, **(ii) per-codebook semantic concentration**, **(iii) drop ablation 영향의 차등화** 세 축으로
검증된다. 지난 2주의 가장 큰 결론은 **v81a (현재 SOTA) 자체가 v62b의 redundancy와 v79c의
collapse 위험 사이의 최적 균형점**이라는 사실이다.

| 차원 | v62b (soft routing) | v79c (hard routing) | **v81a (adaptive top-p, NEW SOTA)** |
|---|---|---|---|
| Raw retrieval (mAP) | 0.6778 | 0.6703 (−0.008) | **0.6879 (+0.010)** |
| 평균 pairwise NMI (off-diag) | 0.641 (높음) | 0.291 (낮음) | **0.461 (중간)** |
| min pairwise NMI | 0.39 | **0.05 (cb3 collapse)** | **0.31 (collapse 없음)** |
| max single-drop ΔmAP | −0.004 (cb0) | −0.009 (cb1) | **−0.007 (cb0)** |
| Drop 영향 분포 | 약함, 거의 평탄 | cb1/cb4 super-load-bearing, cb3 dead | **graded contribution** |
| Unique code 비율 (test) | 0.075 | 0.165 | **0.346 (4.6×)** |
| Codebook collapse 위험 | 없음 (모두 redundant) | **cb3 collapse** | **없음 (모두 활성)** |

→ v81a는 **redundancy를 v62b 대비 −28% 줄이면서 (NMI 0.64 → 0.46), v79c와 달리 codebook collapse를
일으키지 않고, raw mAP도 가장 높다**. 페이퍼에 적합한 SOTA로서의 구조적 근거가 완성된 형태.

### 4-2. v81a per-codebook 상세 분석

**Pairwise NMI matrix** (off-diag, 23K DB):
```
        cb0   cb1   cb2   cb3   cb4   cb5
cb0    1.00  0.35  0.35  0.35  0.36  0.31
cb1    0.35  1.00  0.55  0.55  0.57  0.44
cb2    0.35  0.55  1.00  0.57  0.57  0.50
cb3    0.35  0.55  0.57  1.00  0.55  0.43
cb4    0.36  0.57  0.57  0.55  1.00  0.47
cb5    0.31  0.44  0.50  0.43  0.47  1.00
```

- **cb0 vs rest NMI = 0.31~0.36**: "cb0은 별개 채널" 구조가 v62b에서 v81a까지 일관되게 유지.
- **cb1-5 internal NMI = 0.43~0.57**: v62b의 0.74-0.79에서 크게 감소했으나 0이 아님 → local
  codebook들 사이 적정 수준의 협동 유지 (v79c는 너무 sharp하게 분리시켜 cb3 collapse 발생).

**Per-codebook B1 lift (centered text concentration)**:

| 위치 | v62b | v79c | **v81a** | 해석 |
|---|---:|---:|---:|---|
| C_0 (global) | 0.069 | 0.068 | **0.083** | v81a에서 cb0 specialization 강화 |
| C_1 | 0.050 | 0.055 | 0.045 | 약간 감소했으나 활성 |
| C_2 | 0.045 | 0.042 | 0.042 | 유지 |
| C_3 | 0.049 | **0.003** | 0.047 | v79c collapse vs v81a 정상 |
| C_4 | 0.039 | 0.038 | 0.041 | 유지 |
| C_5 | 0.090 | 0.091 | **0.082** | C_0와 함께 dominant 채널 |

→ v81a의 모든 6개 codebook이 B1 lift > 0.04, **cb3 collapse 없이** cb0/cb5 specialization 강화.
v79c에서 cb3 B1 ≈ 0.003 (random)이었던 collapse 현상이 v81a에서 재현되지 않음.

**Drop ablation — "graded contribution"**:

| Model | Δcb0 | Δcb1 | Δcb2 | Δcb3 | Δcb4 | Δcb5 | 패턴 |
|---|---:|---:|---:|---:|---:|---:|---|
| v62b | −0.0038 | −0.0001 | −0.0010 | −0.0010 | +0.0010 | −0.0016 | cb0만 큼, 나머지 negligible |
| v79c | −0.0034 | **−0.0085** | −0.0020 | +0.0006 | **−0.0056** | −0.0006 | cb1/cb4 specialized, cb3 dead |
| **v81a** | **−0.0066** | −0.0003 | **−0.0045** | **−0.0029** | +0.0001 | +0.0006 | **graded: cb0 > cb2 > cb3 > rest** |

→ v81a는 v62b 대비 cb0 dependence가 strong해지고 (−0.0038 → −0.0066) cb2/cb3가 새롭게 의미
있는 기여를 시작 (각 −0.0045, −0.0029). v79c처럼 일부 codebook이 super-load-bearing이 되는 극단은
피하면서도 v62b의 "전부 redundant" 상태에서 벗어남.

### 4-3. MSCOCO compositional 특성 (mscoco_v78a, mscoco_v81a)

| Model | mAP | 평균 NMI | Δcb0 | C_1-5 평균 Δ | 해석 |
|---|---:|---:|---:|---:|---|
| v63b (이전 base) | 0.4563 | — | −0.019 | +0.0008 (대부분 noise) | local codebook이 *오히려* mild noise |
| mscoco_v69a | 0.4795 | — | −0.017 | ≈ 0 | position-specific decoding이 local cb noise를 mild positive로 전환 |
| mscoco_v78a | 0.4856 | 0.644 | **−0.019** | −0.003 | C_0 압도적 dominant (다른 cb의 5-10×) |
| mscoco_v81a | 0.4891 | (미측정) | (미측정) | (미측정) | 향후 분석 필요 |

→ MSCOCO에서는 **C_0 dominance가 Flickr25k보다 훨씬 극단적**. 80-class fine-grained retrieval에서
C_0이 dominant semantic channel이며, v78a의 adaptive K split이 분할의 69%를 C_0에 흡수시킨 사실이
이 구조와 정확히 일치. **MSCOCO의 effective channel은 사실상 "C_0 1개 + 보조 5개"**.

### 4-4. Compositional 주장의 한계 (페이퍼 limitation section에 기록)

분석 문서의 가장 정직한 결론:

1. **Effective channel은 명목상 6보다 적다.** v81a의 drop ablation에서 cb1/cb4/cb5는 ΔmAP ≈ 0 →
   실질 기여 codebook은 cb0/cb2/cb3로 **3-4 channel이 effective**. cb1-5 internal NMI 0.43-0.57도
   완전 독립이 아닌 부분 중복을 의미.
2. **C_0 dominance가 강화됨.** v81a에서 cb0 drop ΔmAP가 v62b보다 큼 (−0.0066 vs −0.0038).
   compositional 구조가 강해진 만큼 cb0 의존도도 증가.
3. **MSCOCO B1 lift 측정 불가.** 현재 `mscoco_siglip2_v4plus` cache는 10K train 이미지에만 caption을
   저장했고 107K retrieval DB에는 has_text=True 샘플이 0개. text-grounded composition lift는
   별도 train-split extraction이 필요.

### 4-5. 페이퍼 framing 권장 (analysis 문서 §5 발췌)

분석 결과에서 도출한 페이퍼-ready quote:

> "v81a achieves the best of both worlds. Confidence-adaptive top-p routing reduces
> inter-codebook redundancy (mean pairwise NMI 0.641 → 0.461) *without* the codebook
> collapse v79c suffered (cb3 NMI 0.06, B1 ≈ 0). Every codebook contributes measurably
> to retrieval (drop ΔmAP ranging from −0.0066 for cb0 to ≈ 0 for cb4/cb5), and the
> unique-code ratio rises 4.6× over v62b. The compositional-code claim is structurally
> supported: six active channels with graded influence, not six redundant copies."

이는 5/12 시점에 우려되었던 두 가지 문제 — "(i) C_1-5 NMI 0.78 redundant copy 5개", "(ii) single
drop이 mAP 거의 영향 없음 (< 0.4%)" — 를 모두 정량적으로 해소한 증거. 단 위의 한계 (§4-4)는
limitation section에 동시에 명시할 필요가 있음.

## 5. 외부 비지도 Baseline 대비 비교

모두 동일 cache (`flickr25k_siglip2_v3plus` / `mscoco_siglip2_v4plus`), 동일 36-bit 코드, 60 epoch,
batch size 64, 동일 split. 외부 baseline은 별도 head (e.g., CIBHash는 단일 `Linear(768,36)` + paired-aug
NtXent)를 사용.

### 5-1. Flickr25k 비교 (2K query × 23K database)

| Method | Supervision | mAP | P@1 | Unique code 비율 |
|---|---|---:|---:|---:|
| **v81a (ours, NEW SOTA)** | text-on, paired-aug NtXent + adaptive top-p | **0.6879** | **0.7900** | 0.346 |
| v62b (이전 ours SOTA) | text-on, paired-aug NtXent + residual codon | 0.6778 | 0.7625 | 0.075 |
| v34 (text-off ours SOTA) | paired-aug NtXent only | 0.6696 | — | 0.381 |
| v29 (ours, 첫 paired-aug 적용) | paired-aug NtXent | 0.6580 | — | 0.526 |
| CIBHash | paired-aug NtXent on flat `Linear(768,36)` | 0.6543 | 0.8350 | 0.997 |
| CIMON | NtXent + spectral pseudo-labels | 0.6456 | 0.8355 | 0.881 |
| MLS3RDUH | kNN graph + LogCosh | 0.5947 | 0.6780 | 0.184 |

해석:
- **mAP 기준**: v81a가 CIBHash (가장 강력한 외부 비지도 baseline) 대비 +0.034. v29 시점부터 이미
  CIBHash 위였으며, 그 차이를 5/12 → 5/26 사이 **+0.03 추가 확대**.
- **P@1 격차**: 그러나 P@1은 CIBHash 0.835 > v81a 0.790로 여전히 −0.045. CIBHash의 `sign(Linear)`
  구조는 ~0.997 unique한 hash를 만들어 instance-level 식별에는 더 유리.
- **Unique code 비율**: 우리는 compositional codebook 구조 (6×K=64) 때문에 unique가 구조적으로
  낮지만, 5/12 시점 v6 baseline 대비 v81a에서 이 비율이 의미 있게 회복됨 (0.075 → 0.346).

### 5-2. MSCOCO 비교 (5K query × 107K database)

| Method | Supervision | mAP | P@1 | Unique code 비율 |
|---|---|---:|---:|---:|
| CIBHash | paired-aug NtXent on flat `Linear(768,36)` | **0.5051** | **0.7802** | ~0.99 |
| **mscoco_v81a (ours, NEW SOTA)** | position-specific codon + adaptive top-p | 0.4891 | 0.6352 | 0.061 |
| v78a (이전 ours SOTA) | position-specific codon + adaptive K split | 0.4856 | 0.6058 | 0.017 |
| CIMON | NtXent + spectral pseudo-labels | 0.4777 | — | — |
| mscoco_v69a (이전 ours SOTA) | position-specific codon head | 0.4795 | 0.5830 | 0.016 |
| v63b (5/21 baseline) | K=128 + Wasserstein 0.05 + V4 caption | 0.4563 | 0.5606 | 0.315 |
| MLS3RDUH | kNN graph + LogCosh | 0.4434 | 0.6030 | — |

해석:
- **MSCOCO에서는 CIBHash가 여전히 우위** (mAP +0.016, P@1 +0.145). 단 5/21 시점 v63b 0.4563 대비
  −0.049 gap이었던 것이 mscoco_v81a 0.4891 시점 **−0.016까지 감소** (gap 67% 축소).
- 80-class fine-grained multi-label retrieval은 compositional code의 약점. v78a (adaptive K) 시점에서
  C_0 codebook의 capacity를 키워 일부 해결했고, mscoco_v81a (adaptive top-p)에서 routing policy
  자체로 다시 +0.0035 추가 개선.
- **P@1000 (tail retrieval)** 에서는 ours가 더 안정적 (v63b drop −0.030 vs CIBHash drop −0.092):
  CIBHash는 sharp-top / weak-tail profile, ours는 balanced. 응용에 따라 어느 profile이 유리한지는
  use case dependent.

## 6. 현재 실험 방향성

### 6-1. 단기 (다음 1~2주)
1. **mscoco_v81a peak preservation**: v78a ep9가 0.4984로 mscoco_v81a final 0.4891보다 높음.
   - best-epoch checkpoint 선택, 또는 sparsification schedule cap (val effective-k 4.0 이하로 떨어지지
     않도록).
2. **v81a + v79c 스태킹**: routing policy (v81a) + hard routing (v79c)의 결합. 양쪽이 다른 redundancy
   메커니즘을 공격하므로 보완적일 가능성.
3. **v81a Flickr25k → MSCOCO transfer 추가 검증**: 단일 인터벌이 두 데이터셋에서 모두 SOTA였다는
   것이 우연인지 일반적 sweet spot인지 확인.

### 6-2. 중기 (페이퍼-level)
1. **Compositional 주장의 메인 증거를 v81a로 일원화**: 5/26 분석에서 v81a 자체가 redundancy 감소
   (NMI 0.64 → 0.46) + collapse 없음 + 최고 mAP를 동시에 달성. **v62b는 baseline, v81a는 SOTA 겸
   compositional proof, v79c는 "더 sharp한 specialization은 가능하지만 collapse 위험이 있음"의
   ablation point로 역할 분담**.
2. **MSCOCO v81a NMI / drop ablation 측정**: 현재 mscoco_v78a까지만 측정됨 (NMI 0.644, C_0 압도적).
   mscoco_v81a에 대해 동일 분석을 실행해 *cross-dataset SOTA의 compositional 일관성* 확인 필요.
3. **MSCOCO B1 lift 측정 가능하게 cache 확장**: 현재 retrieval DB (107K)에 has_text 샘플 0개라
   text-grounded composition lift 측정 불가. train split 별도 추출 (`extract_train.npz`)을 통해
   페이퍼의 "text grounding" 주장을 MSCOCO에서도 정량화.
4. **2-codebook 동시 drop combinatorial 분석**: v81a의 cb1/cb4/cb5 단일 drop이 ≈ 0이지만 *2개
   동시 drop*은 superadditive할 가능성. effective channel 수의 정확한 정량화에 필요.
5. **MSCOCO CIBHash gap 완전히 좁히기**: 현재 −0.016. position-specific decoding 확장 (codon
   position당 별도 projection MLP) 또는 instance-discrimination loss 추가 검토.
6. **Loss 정리**: `lambda_anchor=0.05`는 EMA 모드에서 무효이므로 페이퍼 표에서 제거 또는 별도
   asterisk 처리 필요. `lambda_dna`, `lambda_bu`에 대해서도 동일 audit 진행 권장.

### 6-3. 비-우선 (검토 후 결정)
- Cosine VQ는 K=64 from-scratch에서 fail. 현재 진행하지 않는 것이 안전.
- Global NtXent는 position-specific decoding과 충돌하므로 페이퍼-level에서 mutually exclusive로 기록.
