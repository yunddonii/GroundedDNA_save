# GroundedDNA 종합 분석 보고서 (2026-05-19)

읽는 사람이 이 한 문서로 프로젝트 전체를 따라잡을 수 있게 작성했습니다.
순서: (1) 무엇을 만들려고 했나 → (2) 어디까지 왔나 → (3) 무엇이 부서졌나
→ (4) 어디로 가야 하나.

---

## 1. 프로젝트의 핵심 주장 (Contribution)

GroundedDNA는 다음 세 가지를 동시에 제공한다고 주장하는 retrieval hashing 모델입니다.

1. **Compositional code** — 36-bit hash를 단일 binary vector가 아니라
   **6 codebook × 3 codon × 2 bit** 구조로 분해.
   각 codebook이 서로 다른 의미 axis(예: "object / scene / color")를
   담당하는 구조적 코드.

2. **Text-supervised routing** — Qwen2.5-VL이 이미지에서 6개의
   part-caption(예: "head, torso, legs, ...")을 추출 → SigLIP2 text
   encoder로 임베딩 → Sinkhorn-OT router의 centroid 역할 → 시각
   patch를 의미 part에 자연어로 grounded routing.

3. **Frozen backbone + tiny trainable head** — SigLIP2 (375M params)를
   동결하고, 위에 얹은 **adapter + codebook + codon head 약 5M params만
   학습**. retrieval 모델로 효율적.

**한 줄로**: "프리트레인된 vision-language 모델 위에, 자연어로 의미 part가
명시된 compositional binary hash를 효율적으로 만든다."

## 2. 지금까지 어디까지 왔나 (실험 요약)

### 2-1. 큰 그림 (mAP 기준 leaderboard, Flickr25k 60 epoch)

| 카테고리 | 대표 모델 | mAP | 비고 |
|---|---|---:|---|
| Supervised SOTA | **v18** (HashNet logistic) | **0.7883** | label 사용. ceiling |
| Supervised baseline | v6 | 0.7556 | label, MSE-Jaccard |
| External supervised | HashNet / CSQ / OrthoHash | 0.76–0.78 | flat binary |
| **Unsupervised SOTA (ours)** | **v34** (paired-aug NtXent, text-off) | **0.6696** | 이 보고서의 기준점 |
| External unsupervised | CIBHash | 0.6543 | flat Linear+NtXent |
| External unsupervised | CIMON | 0.6456 | spectral PL |
| External unsupervised | MLS3RDUH | 0.5947 | kNN graph |
| Text-on best (v40d) | global NtXent K=128, text-on | 0.6280 | text 켜면 −0.042 손실 |

**현재 unsupervised에서는 v34가 우리 SOTA**이고 CIBHash를 +0.015 mAP
이깁니다. 다만 v34는 우리 contribution (2)인 text-supervised routing을
**실제로는 사용하지 않는** 모델이라는 게 핵심 문제 — 4절에서 자세히.

### 2-2. 시간순 진화 (간략)

- **v1–v6 (2026-05-08)**: 기본 파이프라인 정립. v6 = sinkhorn router +
  K=32 codebook + MSE-Jaccard supervised loss → mAP 0.7556.
- **v7–v15 (R-series)**: alignment loss 5종 시도, 전부 regression.
  코드에서 제거.
- **v18 (2026-05-13)**: HashNet logistic loss로 supervised SOTA 0.7883.
- **v27a/b (2026-05-14)**: 처음으로 **unsupervised 시도**. v27a는
  SigLIP2 cosine target → collapse. v27b는 top-k pseudo-positive →
  mAP 0.5639.
- **v29 (2026-05-15)**: **paired-aug NtXent 도입** → unsup mAP 0.6580
  (+0.094 vs v27b). 이때 **text path가 silently 꺼지는 architectural
  bug** 도입됨 (의도하지 않음, 본인이 코드 수정 중 cached_text_part_raw
  를 None으로 전달).
- **v30a (2026-05-15)**: smaller adapter (MLP hidden=768) → 0.6646.
- **v31b**: per-codebook NtXent → 0.6590, compositional metric 1위.
- **v33b**: routing top-k=2 hardening → 0.6594.
- **v34**: v30a + v33b → **0.6696 unsup SOTA**.
- **v35a-f (2026-05-18)**: text path 복구 후 재학습 → **모든 변형이
  −0.04 ~ −0.10 mAP 회귀**. 동시에 compositional metric도 같이 감소.
- **v37a/b**: v22a (per_slot_text_adapter), v22b (visual-attn text
  pooling) 으로 text-on 회복 시도 → 둘 다 추가 회귀.
- **v39**: V3 promptstyle 적용 → 미세 trade-off, 본질 변화 없음.
- **v40a-f (2026-05-18 ~ 19)**: soft routing 복구 후 text-on 환경에서
  per-cb vs global × K=64/128 매트릭스 + scale-up.

### 2-3. v40 시리즈 최종 결과 (soft routing + text-on V1)

| Run | NtXent | K | bs | lr | mAP | B1 | B2 | 메모 |
|---|---|---:|---:|---:|---:|---:|---:|---|
| **v40d** ★ | global | 128 | 64 | 0.001 | **0.6280** | 0.0060 | 0.0150 | text-on에서 best mAP |
| **v40a** | per-cb | 64 | 64 | 0.001 | 0.6156 | **0.0126** | **0.0199** | text-on에서 best compositional |
| v40b | global | 64 | 64 | 0.001 | 0.5976 | 0.0041 | 0.0098 | baseline (=v35b 재현, deterministic) |
| v40e | per-cb | 128 | 64 | 0.001 | 0.5932 | 0.0079 | 0.0170 | per-cb는 K↑가 역효과 |
| v40f | global | 128 | 128 | 0.002 | 0.5863 | 0.0018 | 0.0146 | **2× lr이 codebook EMA 깸**, dead=0.81 |

**v40 시리즈의 4가지 단단한 발견**:

1. **K↑ + global → mAP +0.030** (v40b 0.5976 → v40d 0.6280): global
   NtXent는 큰 코드북 capacity를 활용할 수 있음.
2. **K↑ + per-codebook → mAP −0.022** (v40a 0.6156 → v40e 0.5932):
   per-codebook NtXent는 큰 K가 오히려 손해. 각 codebook이 모든
   negative를 K개 코드로 매핑해야 하는 데 K가 커지면 gradient signal이
   더 많은 codeword로 분산되어 학습 어려움.
3. **per-codebook NtXent가 compositional metric 1위** (v40a B1 0.0126
   > v40d 0.0060): NtXent loss를 codebook별로 분리하면 codebook이 더
   독립적인 cluster를 학습.
4. **단순 linear scaling rule (bs↑ → lr↑) 실패** (v40f): EMA codebook
   update는 learning rate와 무관한 별도 decay (0.99)를 사용하므로,
   gradient lr만 키우면 EMA가 따라잡지 못해서 codebook이 collapse.

## 3. 다른 axis: compositional metric으로 본 trade-off

mAP만이 우리 모델의 가치 척도가 아닙니다. 우리는 codebook 단위로
의미 part를 분해한다고 주장하므로, "**각 codebook이 정말 의미적으로
응집된 cluster를 만드는가**"가 핵심.

`compositional_eval.py`로 두 가지 지표 측정:

- **B1**: 같은 codeword를 선택한 sample들의 SigLIP2 text feature가
  서로 얼마나 비슷한가 (centered cosine). 양수 lift = 의미적 응집.
- **B2**: 같은 codeword를 선택한 sample들의 SigLIP2 visual feature가
  서로 얼마나 비슷한가.

### Pareto plot (대표 모델)

| Run | mAP | B1 lift | B2 lift |
|---|---:|---:|---:|
| **v34** (text-off, mAP 챔피언) | **0.6696** | 0.0162 | 0.0342 |
| **v31b** (text-off, compositional 챔피언) | 0.6590 | **0.0242** | **0.0408** |
| **v40d** (text-on, mAP 챔피언) | 0.6280 | 0.0060 | 0.0150 |
| **v40a** (text-on, compositional 챔피언) | 0.6156 | 0.0126 | 0.0199 |
| **CIBHash** (외부 unsup baseline) | 0.6543 | 측정 불가 | 측정 불가 |

**핵심**: text-off는 compositional metric이 더 높음. 즉 **현재 우리
text supervision은 compositional 구조를 도와주는 게 아니라 약화시키고
있음** — 우리 contribution (2) "text-supervised compositional code"가
실제로 입증되지 않고 있는 상태.

## 4. 모델의 **근본적 문제** 5가지

다음은 단순 hyperparameter 조정으로 풀 수 없는 architectural / 데이터
수준의 본질적 문제들입니다.

### 4-1. SigLIP2 text encoder의 cross-slot uniformity (가장 큰 문제)

**현상**: SigLIP2 text encoder가 우리 6개 Qwen part-caption ("head",
"torso", "legs", ...)을 받으면 6개 출력 벡터가 거의 같은 방향을
가리킴 (cross-slot cos sim ≈ 0.88).

**왜 문제인가**: 우리 Sinkhorn router는 5개 local part centroid가 *서로
다른* 방향을 가리킨다고 가정. 그래야 patch마다 "어느 part가 가장
의미적으로 가까운가" 라는 판단이 가능. 그런데 5개 centroid가 거의 같은
방향이면 router는 모든 patch를 5 part에 거의 균등하게 routing → 5
local codebook이 모두 동일한 patch 분포를 학습 → **redundant codebook
+ dead-code 폭발**.

**증거**:
- v35d 분석에서 **C_0 (global, text-free)는 lift 0.032 healthy, C_1~5
  (local, text-routed)은 모두 lift 0.001~0.005 collapse** 명확히 분리됨.
- v37a (per_slot_text_adapter 6개 독립 MLP) 시도해도 회복 못 함 — 입력
  자체가 cos 0.88이면 6 MLP가 만들 수 있는 출력은 같은 방향의 약간씩
  다른 회전에 불과.
- v22b (visual-attention text pooling) 도 실패 — pooling 방식이
  문제가 아니라 텍스트 임베딩 자체가 collapse되어 있음.

**왜 SigLIP2가 이러는가**: SigLIP2 text head는 **image-caption** 쌍으로
학습됨. caption은 "a photo of a dog playing in the park" 같은 *전체
이미지를 묘사하는 긴 문장*. 우리가 던지는 "head", "torso" 같은 짧고
generic한 part-prompt는 학습 분포 밖이라서 SigLIP2가 의미를 구별 못 함.

---

### 4-2. Text path는 ON일 때 retrieval mAP를 항상 손상시킴

**현상**: text path를 켜면 어떤 setting이든 mAP가 −0.04~−0.10 떨어짐.

| Setup | text-off mAP | text-on mAP | Δ |
|---|---:|---:|---:|
| v30a → v35b | 0.6646 | 0.5976 | −0.067 |
| v31b → v35d | 0.6590 | 0.6242 | −0.035 |
| v34 → v35f | 0.6696 | 0.6073 | −0.062 |
| v34 → v40d (soft K=128) | 0.6696 | 0.6280 | −0.042 (가장 작은 손실) |

**왜 문제인가**: 우리 contribution (1) "compositional code"와 (2)
"text-supervised routing"이 사실 **서로 충돌하는 objective**라는 것을
의미. text supervision이 visual clustering의 자유도를 빼앗아 retrieval
성능을 깎고, 그 대가로 받아야 할 compositional structure 향상은 4-1
때문에 일어나지 않음. **양손에 떡 = 양손 모두 떨어뜨림**.

**원인 추정**:
- text centroid가 uniform → routing이 visual clustering의 정보를 약화
- L_anchor가 codebook을 (uniform한) text 방향으로 끌어 visual
  discrimination 약화
- codebook EMA가 visual + text 두 신호의 noise에 흔들림

---

### 4-3. Per-codebook NtXent의 capacity 한계

**현상**: per-codebook NtXent (v31b, v40a)는 compositional metric은 1위지만
mAP는 global보다 낮음. K를 키우면 (v40e) 둘 다 떨어짐.

**왜인가**: per-codebook NtXent는 "각 codebook의 3-codon 블록 (4³=64개
가능 코드) 으로 batch 내 2B=128 sample을 distinct하게 식별"하라는 요구.
이건 **pigeonhole 원리상 항상 불완전**.
- K=64: 128 sample을 64 code로 매핑 → 평균 2 sample/code → loss에 항상
  irreducible collision 항.
- K=128: codebook embedding 공간은 커지지만 출력 코드 공간(4³)은
  그대로. 게다가 더 많은 codeword에 gradient가 분산되어 학습 어려움.

**증거**: v31b의 per-codebook unique=0.0099 (각 codebook은 평균 ~20개
코드만 활용). global v34는 unique=0.0003 (각 codebook은 ~1개 코드만
활용). per-codebook은 codebook을 다양화시키지만 *최대 식별력*에 천장이
있음.

---

### 4-4. Compositional 절대값이 작음 (B1 lift 0.02 수준)

**현상**: 우리의 가장 강한 compositional 결과 (v31b) B1 lift = 0.0242.
random baseline 대비 +2.4% 정도. 절대값으로 "codebook 1 = 색깔" 같은
crisp 의미 부여는 안 됨 (qualitative image grid에서도 약한 theme만 보임).

**왜 문제인가**: paper narrative상 "compositional code"가 mAP가 아닌
무엇으로 가치를 증명할지 모호. CIBHash는 unique=0.997 (사실상 instance
hash)로 우리를 압도하고, 우리 compositional metric은 절대값이 작아
"미세한 통계적 차이"로만 입증.

**왜 작은가**:
- Flickr25k train set 5K개. K=64 codeword × 6 codebook 공간을 학습할
  데이터가 부족.
- text supervision이 부재 (4-1, 4-2) → codebook이 자연어 의미로
  ground되지 못함, 순수 visual cluster만.

---

### 4-5. EMA codebook update의 hyperparameter 민감도

**현상**: v40f (lr 2배) → codebook이 catastrophic collapse (dead=0.81,
unique=0.001). v33a (eps anneal too aggressive) → 7.5% dead.

**왜 문제인가**: gradient-based learning rate와 EMA decay는 독립
hyperparameter지만 실제로는 상호작용. lr↑면 새 codeword가 더 빨리
움직이는데 EMA는 0.99 고정 → mismatch로 codebook 일부가 영구 unused.

**증거**: EMA codebook revival 정책이 일부 dead code 회수에 성공
(v34의 dead=0.000) 하지만 catastrophic collapse는 회수 불가
(v40f의 dead 변화 0.857 → 0.807, 60 epoch에 거의 회복 없음).

---

## 5. 해결 방향 (실행 가능한 순서대로)

위 5개 문제를 정확히 짚어 푸는 길:

### Tier 1 — 가장 즉시 시도 가능 (1~3일, 큰 효과 기대)

#### 5-A. **다른 text encoder로 교체** (문제 4-1 직접 공격)
- SigLIP2 text head 대신 **CLIP / BERT / E5 / T5** 등 짧은 prompt에
  강한 인코더로 part-caption 임베딩.
- 기대: cross-slot cos sim 0.88 → 0.5 미만으로 떨어지면 text routing이
  실제로 5 local part를 분리 → 4-2 문제도 같이 해소.
- 작업량: cache 빌드 (~20분) + 모델에 text 인코더 선택 flag 추가
  (~30 LoC).
- 위험: 잘못된 인코더는 더 안 좋을 수 있음. 여러 개 동시 비교 필요.

#### 5-B. **Cross-slot decorrelation loss** (문제 4-1 직접 공격)
- text_adapter 출력 `t[B, 6, D]`에 명시적 제약: 임의의 두 slot
  m ≠ m'에 대해 `cos(t[:, m, :], t[:, m', :])`을 최소화.
- 즉 6 slot이 *직교* 방향으로 강제. SigLIP2 인코더는 그대로 두고
  adapter에서 분리.
- 기대: 본질적 SigLIP2 한계를 우회 — text uniformity가 adapter 단계
  에서 깨짐.
- 작업량: loss term 추가 (~15 LoC), λ_decorr hyperparameter.
- 위험: adapter가 정보를 잃고 noise만 직교화할 수 있음. λ 신중히 시작
  (0.01).

#### 5-C. **풍부하고 part-specific한 Qwen prompt 재생성** (문제 4-1 우회)
- 현재 prompt: "describe the head"
- 새 prompt: "Looking at the head specifically, describe what you see
  that is DIFFERENT from the rest of the image. Focus on colors,
  textures, and shapes unique to this region."
- SigLIP2 인코더는 그대로 두고 입력 caption만 더 다른 방향으로
  유도하면 cos sim 떨어질 가능성.
- 작업량: prompt rewriting + Qwen 재실행 (~30분) + cache 재빌드.

### Tier 2 — 중간 난이도 (3~7일, 중간 효과 기대)

#### 5-D. **per-codebook + global NtXent 가중 합산 (v31a)**
- 지금까지 둘 다 단독으로만 시도 (v31b는 per-cb only, v34는 global only).
- additive variant: `λ_global · L_global + λ_per_cb · L_per_cb`.
- 기대: mAP 챔피언 (v34) + compositional 챔피언 (v31b)의 strict
  Pareto. v40 결과로 봐도 두 loss가 충돌하지 않을 가능성 있음.
- 작업량: loss aggregator에 두 mode 동시 활성 옵션 (~20 LoC).

#### 5-E. **MoCo-style memory bank**
- 현재 NtXent는 batch 64 내 128 sample만 비교. MoCo는 65K queue 사용.
- 기대: 8~16% mAP 향상 가능 (paper 평균치). text-on regime의 0.60
  영역을 0.65+로 끌어올릴 잠재력.
- 작업량: queue dataclass + momentum encoder + dequeue/enqueue 로직
  (~200 LoC). codebook EMA와 조합 안전성 확인 필요.

#### 5-F. **Per-codebook K 비대칭화**
- 현재 모든 codebook K=64로 동일. 의미 part마다 다양성이 다를 수 있음
  (예: "color"는 적은 K, "object class"는 많은 K).
- 학습 가능한 K (codebook usage 통계 기반 동적 할당) 또는 manual
  prior로 codebook별 K 차별화.
- 작업량: quantizer 수정 (~100 LoC).

### Tier 3 — 본질적 재설계 (1~2주, 큰 효과 또는 새 narrative)

#### 5-G. **Text supervision을 routing → quantization으로 이동**
- 현재 text는 router centroid로만 사용 → 4-2 문제.
- 새 디자인: text를 **codebook embedding의 초기값/anchor**로 사용.
  - 각 codebook m의 첫 K_text codeword를 Qwen captions의 SigLIP2 text
    임베딩으로 초기화.
  - 나머지 K - K_text는 random.
  - 학습은 visual NtXent로 하되 text-anchored codeword들이 의미 ground
    역할.
- 기대: text가 routing 신호를 망치지 않고 codebook semantic anchor로
  순수하게 기여.

#### 5-H. **Compositional 평가 axis 강화 + paper narrative 재정의**
- 현재 B1/B2 lift만으로는 compositional 주장이 약함 (4-4).
- 새 metric: per-codebook retrieval mAP (각 codebook 단독으로 retrieval
  얼마나 가능한가), codeword-text alignment (각 codeword가 어떤 text
  concept과 가장 가까운가), compositional generalization
  (codebook 일부만 fix하고 나머지 변화 → semantic swap).
- 이게 우리만의 axis. CIBHash는 axis 자체가 없음.
- 작업량: 평가 코드만, 모델 변경 없음 (~300 LoC).

#### 5-I. **다른 데이터셋으로 일반화 검증**
- Flickr25k 5K train은 너무 작음. MSCOCO (~80K), NUS-WIDE (~150K)
  에서 같은 패턴 재현되는지 확인.
- 캐시는 v6 시점에 일부 빌드되어 있음 (NUS-WIDE는 중단됨).
- 기대: 더 큰 train set에서 compositional metric이 살아날 가능성 (4-4
  부분 해결).

## 7. 한 줄 정리

> **현재 unsupervised SOTA v34 (mAP 0.6696)는 우리 contribution (1)
> compositional만 일부 입증하고 (2) text-supervised는 사실상 사용 안 함.
> 진짜 우리 모델이 되려면 SigLIP2 text encoder의 uniformity 문제를

> 까지는 compositional metric을 새 axis로 정량화해 narrative를 보강하는
> 것이 학회 임팩트에 가장 빠르게 도움 됨.**
